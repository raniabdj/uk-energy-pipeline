# PySpark / Databricks version

A second implementation of this project's silver layer, written in PySpark instead of
pandas, built to run on [Databricks Community Edition](https://www.databricks.com/try-databricks)
(free, no billing required).

The main project (`../src/`) uses pandas for simplicity and because the data volume doesn't
need distributed compute. This version demonstrates the same bronze → silver → gold logic
expressed as Spark DataFrame transformations — the pattern production Databricks/Fabric
pipelines are built on once data volume grows past what a single machine handles.

## Running it

**On Databricks Community Edition (recommended):**
1. Sign up for a free Community Edition workspace
2. Workspace → Import → upload `transform_pyspark.py`
3. Upload bronze JSON files (generated by the main project's `src/extract.py`) to
   DBFS under `/FileStore/bronze/`
4. Attach the notebook to a cluster and run all cells

**Locally, for testing:**
```bash
pip install pyspark
python transform_pyspark.py path/to/a/regional_bronze_file.json
```

## What changed vs. the pandas version

| | pandas version (`../src/transform.py`) | PySpark version (this file) |
|---|---|---|
| Engine | pandas, single machine | Spark, distributable across a cluster |
| Nested JSON handling | manual dict/list iteration | `F.explode()` on Spark arrays/structs |
| Output | Parquet/CSV on local disk | Delta table on a Databricks lakehouse |

The underlying logic — flatten regional fuel-mix data, rank regions by carbon intensity —
is identical. Only the execution engine changes, which is the point: the same
transformation logic scales from a laptop to a cluster without being rewritten from scratch.
